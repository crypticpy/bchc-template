{%- comment -%} Entry image, resolved honestly — no generated placeholder. Usage: {% include entry-thumb.html entry=page img_class="rounded-md" %} Params: entry (required, an entry page object), img_class (extra classes on the ), eager (optional; true = loading="eager" for above-the-fold cards, default lazy), fetchpriority (optional; true = fetchpriority="high" — pass it for the ONE image that is the page's LCP candidate, never for a row of them). Fallback order: explicit `thumbnail` front matter -> the first image of the first `images`-type schema field -> `thumb.jpg` when it exists on disk -> NOTHING. Callers MUST treat empty output as "this entry has no picture" and omit the media band entirely (capture the include and check for blank), per design-brief principle 5. Presentation-only front matter, like `thumbnail`/`thumbnail_alt` and deliberately not in schema.yml (it describes one picture, not the entry): thumbnail_focus a CSS object-position, default "center top" — the media band is 16:7 and the top is where a deck or a dashboard puts its title. No width/height: the only size CI can promise is the 800px width from .github/workflows/thumbnails.yml (`pdftoppm -scale-to-x 800 -scale-to-y -1` keeps the source's aspect ratio, so the height varies by deck), and the media band reserves its own box with aspect-[16/7] anyway. A guessed height would be a lie for no layout gain.
